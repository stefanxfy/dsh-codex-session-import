# DSH Codex Recent Import

将本地 Codex 主会话的近期历史导入已有 DSH 工作区的独立插件。当前版本 **0.1.28**。导入仅在本地处理，不做 AI 摘要。

Local Codex conversation history importer for DeepSeek Harness. Preview first; no historical tool execution or automatic resume. This is an independent project, not an official DSH plugin.

## 功能与边界

- 按源工作区筛选、搜索、多选会话，支持跨 worktree 保留选择；前端仅提供主会话入口，固定排除归档与独立子代理日志。
- 以每份源日志**首个会话头 `session_meta`**确定身份，不允许后续继承的父会话头覆盖它，避免子代理误当主会话或套用父标题。合法同名主会话／用户分支不会按标题合并或删除。
- 默认保留最近 **30 个真实用户轮次**，可调 **1–500**；更早历史直接跳过，不生成 AI 摘要。环境、页面及运行时注入内容不计作真实用户请求。
- 默认阅读／续聊适配（`readable-v2`），也可选完整审计；工具输出默认保留首尾共 **8000 字符**，可调 **256–64000**，显示丢弃计数，不切坏参数 JSON。
- 逐项预览、顺序批量写入、错误隔离、取消剩余任务和失败重试。不会修改 Codex 源日志或覆盖已有 DSH 会话。
- 标题沿用源会话原名，不自动添加“（适配版）”等后缀；已有导入会话不会自动改名。
- 导入仅创建历史会话，不执行工具、不恢复原多代理运行状态、不启动实时 agent，也不自动发送提示或续跑；不迁移记忆、Skills、自动化，不同步仍在增长的活跃会话。

## 运行要求与接入

需要 **Node.js >=24**、**DSH >=0.2.2-rc.5 且 <0.3.0-0**，会话格式必须为 **Session v4**。版本范围来自 [package.json](<package.json>)，不代表范围内所有版本均已逐一验收。

插件使用 DSH 提供的 Connection、工作区和会话持久化服务，不依赖模型服务，不能当作独立网页或命令行导入器运行。通过 DSH 支持的插件管理流程加载并启用。入口与 bundle patch 见 [package.json](<package.json>)；升级后需重新加载前后端。阅读适配能力握手失败时阻止预览／导入，不静默退回旧模式。

桌面与 Web 均使用宿主已认证的逻辑 RPC，只有 owner 可访问导入接口。无需为插件另开未认证的本地 HTTP 服务。

## 使用流程

1. 打开侧栏 **Codex 会话导入**。页面显示版本，采用来源／逐会话预览／设置三栏布局，窄屏重排。普通预览只显示简明统计和必要运行提示；按字符阈值粗估的续聊上下文提示不在界面展示，这不代表后续续聊保证不超限，不展示历史轮次正文、原始时间戳、调试 JSON、常规处理说明或核查按钮；也不显示摘要与费用确认控件。
2. 检查 CODEX_HOME 来源。目录无待应用变更时点击“刷新会话列表”；填写或更改目录后点击“应用目录并扫描”。选择源工作区、搜索并勾选主会话。
3. **选择目标 DSH 工作区**，设置保留轮数 N、阅读／审计方式和工具输出长度。目标不代选；无目标时先在 DSH 创建或打开工作区，再刷新。
4. 点击 **预览所选**，本机读取固定源快照并检查轮次、裁剪计数与运行告警，不发送模型请求。
5. 点击 **确认并开始导入**。流程只有 **preview → start**。选择、目标或参数变化、源变化或令牌过期后需重新预览。
6. 成功后会自动请求刷新 DSH 原生会话目录，不提供手动刷新按钮。刷新失败单独提示重新打开导入页面以再次自动刷新，不否定已完成写入，也不要重新导入。取消不会删除已写入会话，失败项可重试。

## CODEX_HOME：自动发现与手动指定

发现顺序为：已应用的手动目录 → DSH 后台进程环境变量 `CODEX_HOME` → 当前用户默认 `.codex`。环境候选不可用时继续检查默认目录。界面显示实际目录及发现方式；自动发现填入输入框不等于改为手动设置。

手动目录必须是绝对、可读目录，并含可读的 `sessions` 或 `archived_sessions` 子目录（但前端仍不导入归档）。应用后只写插件私有来源配置，不修改系统环境。清空并应用恢复自动发现；切换来源使旧选择和预览失效，兼容详情 API 仍绑定原来源。

- macOS／Linux 使用 DSH 后台进程可访问的本地路径。macOS 从 Dock 启动可能不继承 shell 环境，此时手填；插件不执行 shell 配置文件。
- Windows 可使用本机绝对路径；访问 WSL 时可手填 UNC，例如 `\\wsl.localhost\Ubuntu\home\<user>\.codex`。若 DSH 后台运行在 WSL 内，则使用 Linux 路径。
- 插件不启动 WSL、不挂载目录、不转换任意 Windows／Linux 路径。需先保证发行版与目录对 DSH 后台可访问。
- Windows／WSL 的路径语义测试不等于实机验收；本项目不声称已完成 Windows／WSL 实机或跨平台端到端验收。

## 阅读适配、原生 reasoning 与审计

`readable-v2` 是**本地确定性格式适配，不是模型生成**。每会话加入中文安全说明，历史工具按轮汇成摘要；运行时工具定义移入有界只读详情，普通代码／JSON 讨论保留。主日志已有的子代理调用／返回保留为历史，不递归读取独立子代理日志。

结构化 `agent_message` 转为中文、不可执行的协作历史说明；内部 ID、路由及经脱敏的结构仅在兼容详情 API 的有界数据中保留，不把整段内部 JSON 塞进正文。原日志已有的可读推理摘要保留在 DSH **原生 reasoning／思考区**，不额外生成推理、不解密加密内容、不补写结论。展开／收起由 DSH 决定；视觉折叠不等于减少上下文 token。

完整审计模式保留原审计转换兼容性。API 未提供 presentation 时仍默认审计，前端明确选择阅读模式。转换版本参与去重；不升级 readable-v2，不重写旧会话。兼容详情 API 核查旧记录时仍区分原转换版本与本次解析版本。

来源详情仅留作兼容的 owner-only API，界面不再提供核查入口。该 API 只读、分页且有长度预算，不生成摘要或写入会话。源日志缺失或固定前缀改写时会明确提示无法核查。新导入不再保存导入后的来源快照；旧格式记录若已有快照，仍保留兼容核查，但不会显示导入历史列表，也不自动清理旧记录。

## 只保留最近 N 轮，不做 AI 摘要

- historyMode 仅支持 truncate，默认即本地截断；没有摘要策略下拉或费用二次确认。
- 旧客户端显式请求 summary 或 confirmSummary=true 会被拒绝，不会读源估算或访问模型。
- 插件不注入 llm／agentDefaultModel，不调用摘要模型，不读写摘要缓存；已有导入会话、摘要与缓存不修改。
- 去重仍区分导入参数：新截断版与旧摘要版不是同一组合。旧记录保留，不强行迁移或视作等价。

## 快照、去重与数据保护

预览绑定固定源字节范围及 SHA-256，后续追加不纳入快照；兼容详情 API 重验相同固定前缀。最终导入使用已确认预览，不自动读取源文件新内容。分支缺失祖先前缀不保证完整恢复；镜像和 compacted replacement 不重复追加。

插件 manifest 按**源快照、导入选项／转换版本、目标工作区**去重，相同记录明确跳过。新写入项只保存去重键对应的 DSH 会话 ID，不再额外保存标题、来源路径／快照、选项或工作区展示信息；页面不展示“已导入会话”列表或“曾导入”标记。旧格式记录继续用于去重，不自动修改或清理。它**不查询 DSH 中会话是否已归档或删除**，也**没有强制重新导入功能**；目标会话被删除后，原 manifest 仍可能阻止相同组合再次导入。

私有数据默认位于用户主目录的 `.dsh/codex-recent-import/`，当前读写来源配置和最小去重 manifest。旧摘要缓存保持原样，不读取、更新或自动删除；坏旧摘要缓存不应阻断本地导入。新去重值仅为 `{id}`，旧格式项可能含源快照，均可能敏感，不应提交公开仓库。写入请求目录0700／文件0600，实际权限语义取决于平台。

历史文本、工具输出和协作消息都是不可信数据，不升级为当前系统指令或执行授权。插件不记录原始会话正文到错误日志，不增加评分或遥测。公开截图只能使用合成或充分脱敏样本；本说明不附真实会话截图。

## 资源限制与失败处理

预览默认空闲有效期15分钟，每批最多24份、合计64MiB；以服务端实际上限为准。超限拒绝，不静默淘汰本批令牌；大批次请拆分。不再提供摘要超时或摘要缓存策略。

插件的有效资源配置包括 `previewTtlMs`、`maxPreviewBytes`、`maxPreviews`、`maxJobs`、`contextWarningChars` 与 `cacheRoot`；正整数边界由实际服务校验。旧版本摘要配置不再启用摘要能力。

图片仅保留占位，不代表原图已迁移；加密内容不解密。较大的N可能超出后续续聊模型上下文，导入成功不保证下一次模型调用成功。当前插件只准备最近N轮，不积累更早历史用于AI摘要，仍不保证任意规模文件一次处理成功。

持久化成功但工作区绑定失败时报告孤立制品标识，不自动删除；重试前需核查。manifest 写入失败会警告，重启后可能重复导入。
