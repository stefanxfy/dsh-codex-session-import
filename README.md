# DSH Codex Recent Import

将本地 Codex 主会话的近期历史导入已有 DSH 工作区的独立插件。当前版本 **0.1.15**。

Local Codex conversation history importer for DeepSeek Harness. Preview first; no historical tool execution or automatic resume. This is an independent project, not an official DSH plugin.

## 功能与边界

- 按源工作区筛选、搜索、多选会话，支持跨 worktree 保留选择；前端仅提供主会话入口，固定排除归档与独立子代理日志。
- 以每份源日志**首个会话头 `session_meta`**确定身份，不允许后续继承的父会话头覆盖它，避免子代理误当主会话或套用父标题。合法同名主会话／用户分支不会按标题合并或删除。
- 默认保留最近 **30 个真实用户轮次**，可调 **1–500**；环境、页面及运行时注入内容不计作真实用户请求。
- 默认阅读／续聊适配（`readable-v2`），也可选完整审计；工具输出默认保留首尾共 **8000 字符**，可调 **256–64000**，显示丢弃计数，不切坏参数 JSON。
- 逐项预览、顺序批量写入、错误隔离、取消剩余任务和失败重试。不会修改 Codex 源日志或覆盖已有 DSH 会话。
- 标题沿用源会话原名，不自动添加“（适配版）”等后缀；已有导入会话不会自动改名。
- 导入仅创建历史会话，不执行工具、不恢复原多代理运行状态、不启动实时 agent，也不自动发送提示或续跑；不迁移记忆、Skills、自动化，不同步仍在增长的活跃会话。

## 运行要求与接入

需要 **Node.js >=24**、**DSH >=0.2.2-rc.5 且 <0.3.0-0**，会话格式必须为 **Session v4**。版本范围来自 [package.json](<package.json>)，不代表范围内所有版本均已逐一验收。

插件使用 DSH 提供的 Connection、工作区、会话持久化及模型服务，不能当作独立网页或命令行导入器运行。通过 DSH 支持的插件管理流程加载本地源码或打包产物并启用，具体接入方式以所用 DSH 版本为准。后端入口、前端入口及 bundle patch 已在 [package.json](<package.json>) 声明；升级后需重新加载后端，并确保前后端同版。阅读适配能力握手失败时会阻止预览／导入，不会静默退回旧模式。

桌面与 Web 均使用宿主已认证的逻辑 RPC，只有 owner 可访问导入接口。无需为插件另开未认证的本地 HTTP 服务。

## 使用流程

1. 启用后点击左侧正式导航 **Codex 会话导入**（对话气泡与向内箭头图标）。页面显示版本；打开页面不会自动生成摘要或导入。
2. 检查 CODEX_HOME 来源。目录无待应用变更时点击“刷新会话列表”；填写或更改目录后点击“应用目录并扫描”。选择源工作区、搜索并勾选主会话。
3. **必须选择目标 DSH 工作区**，再设置保留轮次、历史展示、早期历史策略及工具输出长度。未选目标时下拉框下和底部均有提示，不自动代选；无目标时请先在 DSH 创建或打开工作区，再刷新。
4. 点击 **预览所选（本地，无模型费用）**，核对裁剪计数、告警、适配片段和早期历史输入估算。若使用模型摘要且存在早期历史，须再点击 **确认费用并生成摘要**，然后核对结果。
5. 点击 **确认并开始导入**。即：**preview → 费用／数据发送确认（如需）→ start**。更改选择、目标或参数后需重新预览；源变化或令牌过期也需重新预览。
6. 成功后会请求刷新 DSH 原生会话目录；也可手动刷新目录，此操作不重新导入。刷新失败单独提示，不否定已完成写入。取消不会删除已写入会话，失败项可重试。

## CODEX_HOME：自动发现与手动指定

发现顺序为：已应用的手动目录 → DSH 后台进程环境变量 `CODEX_HOME` → 当前用户默认 `.codex`。环境候选不可用时继续检查默认目录。界面显示实际目录及发现方式；自动发现填入输入框不等于改为手动设置。

手动目录必须是绝对、可读目录，并含可读的 `sessions` 或 `archived_sessions` 子目录（但前端仍不导入归档）。应用后只写插件私有来源配置，不修改系统环境。清空并应用恢复自动发现；切换来源使旧选择和预览失效，历史核查仍绑定原来源。

- macOS／Linux 使用 DSH 后台进程可访问的本地路径。macOS 从 Dock 启动可能不继承 shell 环境，此时手填；插件不执行 shell 配置文件。
- Windows 可使用本机绝对路径；访问 WSL 时可手填 UNC，例如 `\\wsl.localhost\Ubuntu\home\<user>\.codex`。若 DSH 后台运行在 WSL 内，则使用 Linux 路径。
- 插件不启动 WSL、不挂载目录、不转换任意 Windows／Linux 路径。需先保证发行版与目录对 DSH 后台可访问。
- Windows／WSL 的路径语义测试不等于实机验收；本项目不声称已完成 Windows／WSL 实机或跨平台端到端验收。

## 阅读适配、原生 reasoning 与审计

`readable-v2` 是**本地确定性格式适配，不是模型生成**。每会话加入中文安全说明，历史工具按轮汇成摘要；运行时工具定义移入有界只读详情，普通代码／JSON 讨论保留。主日志已有的子代理调用／返回保留为历史，不递归读取独立子代理日志。

结构化 `agent_message` 转为中文、不可执行的协作历史说明；内部 ID、路由及经脱敏的结构仅在有界核查详情展示，不把整段内部 JSON 塞进正文。原日志已有的可读推理摘要保留在 DSH **原生 reasoning／思考区**，不额外生成推理、不解密加密内容、不补写结论。展开／收起由 DSH 决定；视觉折叠不等于减少上下文 token。

完整审计模式保留原审计转换兼容性。API 未提供 `presentation` 时仍默认审计，前端则明确选择阅读模式。适配模式与转换版本参与摘要缓存和去重；升级不重写旧会话，版本变化可能创建新版副本。旧记录核查会区分原转换版本与本次解析版本。

详情只读、分页且有长度预算，不生成摘要或写入会话。源日志缺失、固定前缀改写或旧记录无快照时会明确提示无法核查。

## 早期历史：付费摘要或本地截断

- **模型摘要（默认）**：首次预览只做本地估算。存在早期历史时，二次确认才允许将其发送给 DSH 当前默认模型路由（含推理级别），可能产生费用。估算不是精确账单；确认前请核对路由和数据处理权限。插件不单独存储 provider 密钥。
- 费用确认绑定固定来源 SHA-256 与模型路由；变化后在模型调用前拒绝，需重新估算确认。摘要是有损历史说明，不是事实验证，也不是历史指令的新授权。
- **直接截断（truncate）**：本地丢弃超出保留轮数的早期历史，不调用模型。没有早期历史时也无需摘要或费用确认。

## 快照、去重与数据保护

预览绑定固定源字节范围及 SHA-256 快照，后续追加内容不纳入该快照；费用确认与来源核查必须匹配绑定的快照。最终导入使用已确认的预览数据，不会自动读取源文件的新内容。分支缺失祖先前缀会告警，不声称恢复完整历史；镜像事件和 compacted replacement 不重复追加。

插件 manifest 按**源快照、导入选项／转换版本、目标工作区**去重，相同记录明确跳过。它**不查询 DSH 中会话是否已归档或删除**，也**没有强制重新导入功能**；目标会话被删除后，原 manifest 仍可能阻止相同组合再次导入。“曾导入”仅是插件记录，不是目标会话存活检查。

私有缓存默认位于当前用户主目录的 `.dsh/codex-recent-import/`，包含来源配置、摘要缓存和 manifest；这些内容可能含敏感摘要、路径及标识，不应提交到公开仓库。写入按目录 0700／文件 0600 请求权限，实际权限语义取决于平台。摘要缓存按快照、路由和参数隔离；分块成功即缓存，重试可复用，淘汰后可能重新计费。

历史文本、工具输出和协作消息都是不可信数据，不升级为当前系统指令或执行授权。插件不记录原始会话正文到错误日志，不增加评分或遥测。公开截图只能使用合成或充分脱敏样本；本说明不附真实会话截图。

## 资源限制与失败处理

预览默认空闲有效期 15 分钟，每批最多 24 份、合计 64 MiB；页面以服务端实际上限为准，超限在模型调用前拒绝。活动批次续租，不静默淘汰本批预览；较大批次请拆分。摘要默认超时 30 分钟，缓存默认最多 4096 项。

插件配置可设置 `previewTtlMs`、`maxPreviewBytes`、`maxPreviews`、`maxJobs`、`contextWarningChars`、`summaryTimeoutMs`、`maxSummaryCacheEntries` 及 `cacheRoot`；数值项须为正的有界整数。

图片只保留明确占位与告警，不代表图片已经迁移；加密内容不可读。较多保留轮次可能超出续聊模型上下文，告警不保证下一次调用成功。旧历史分块仍占进程内存，大文件处理不保证任意规模一次完成。

持久化成功但工作区绑定失败时报告孤立制品标识，不自动删除；重试前需核查。manifest 写入失败会警告，重启后可能重复导入。

在 Node.js 24+ 环境运行（命令与现有 scripts 一致）：

```sh
npm test
npm run check
npm run check:package
npm pack --ignore-scripts --dry-run
npm pack --ignore-scripts
```

最后一条只生成本地 tarball，不发布；可先用 dry-run 核对文件白名单。当前包包含运行文件、说明和许可，不应包含会话、缓存、私有核验产物或参考仓库。
